# SEO и 26 языков

## Задано

Поддержка 26 языков и S3 JSON с готовыми переводами. Список языков и основной язык не предоставлены. Нельзя подменять их произвольным перечнем из 26 кодов.

## Предлагаемая модель локализации

Единый реестр locale: код, название, направление письма, доступность, базовый язык и стратегия fallback. Отделять переводы интерфейса от переводов редакционного и пользовательского контента. Готовый JSON не означает автоматический перевод переписки или всех публикаций.

До реализации утвердить схему ключей и версионирование словарей. Проверять пропущенные ключи, параметры подстановок, plural forms, форматы дат и чисел, длину текста. RTL включать, если он нужен для утверждённого набора языков.

Предложение маршрутов: `/{locale}/...`; выбор между префиксом для всех языков и исключением основного открыт. Явный выбор пользователя сохранять; не делать недоступными прямые ссылки из-за автоматического определения языка.

## Предлагаемые SEO-правила

Публичный контент отдавать в индексируемом HTML с уникальными title и description. Canonical должен отражать реальный основной URL конкретной языковой версии. hreflang строить только для существующих эквивалентных переводов с взаимными ссылками. Не объявлять fallback-текст полноценным переводом.

Разделить sitemap по типу или языку по необходимости. Страницы входа, настройки, личные диалоги и внутренние инструменты исключать из индексации; noindex не является контролем доступа. При смене публичных slug — постоянное перенаправление и обновление внутренних ссылок.

.org и .com должны иметь различимые назначения страниц; при дублировании материалов нужна явная стратегия canonical/перепубликации. Структурированные данные добавлять по фактическому типу материала; новостной контекст не делает любую страницу NewsArticle.
