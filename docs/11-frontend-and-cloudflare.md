# Next.js, Mantine и Cloudflare

[Оглавление](README.md) · [SEO](08-seo-and-localization.md) · [Развёртывание](12-infrastructure-and-monorepo.md)

## Задано

Next.js и Mantine; frontend на Cloudflare. Go backend расположен в общей архитектуре с Hetzner. Expo/React Native и Node упоминаются в вопросе исходной беседы как альтернативы; содержание ответа не прочитано. Текущий запрос задаёт Next.js и Go как выбранный стек.

## Предлагаемая ответственность frontend

Маршруты, интерфейс, отображение локализованного контента, публичный SEO HTML и защищённый пользовательский опыт. Mantine — основа компонентов и темы. Единую тему использовать для .org и .com при различии информационной архитектуры.

Серверные и клиентские части разделять по потребности: приватные данные не включать в публичные статические страницы и общие кэши. Токены, секреты интеграций и прямые подключения к PostgreSQL не передавать в браузер.

## Открытый блок совместимости

Точный продукт Cloudflare, адаптер Next.js, версии, поддерживаемые серверные возможности и стратегия сборки не выбраны этим документом. Проверить их по актуальной официальной документации при реализации. Утверждать совместимость полного Node runtime с edge без проверки нельзя.

Проверочный прототип должен охватить SSR/SEO, локализацию, стили Mantine и hydration, cookies входа, API-проксирование, кэш-инвалидацию и транспорт мессенджера. До этого не фиксировать конкретные версии и команды деплоя.

## Предлагаемая граница сети

Браузер → Cloudflare frontend → Go API на Hetzner или отдельный API hostname. Выбор влияет на cookies, CORS, CSRF и real-time. Персональные ответы не кэшировать общим CDN. Origin защищать и аутентифицировать в соответствии с выбранной сетевой схемой.

Открыто: единый origin или отдельный API-домен, независимый .org frontend, изображения, наблюдаемость edge, preview-окружения и поведение при недоступном backend.
