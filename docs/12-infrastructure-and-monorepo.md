# Hetzner, Docker Compose и монорепо

[Оглавление](README.md) · [Backend](10-backend-and-data.md) · [Риски](13-decisions-risks-and-roadmap.md)

## Задано

Hetzner, Docker Compose и монорепо. Конфигурации, серверы, учётные записи и доменные настройки не проверялись и не изменялись.

## Предлагаемая топология

Cloudflare обслуживает Next.js frontend; Hetzner размещает Go API, PostgreSQL, Redis и, если выбран такой runtime, процесс Content Sync Worker. S3 JSON расположен в отдельно выбранном S3-совместимом хранилище. Не отождествлять S3 с Cloudflare R2 или Hetzner Object Storage без решения.

Docker Compose описывает серверные сервисы, внутренние сети, тома и проверки здоровья. БД и Redis не публикуются в интернет. Внешний трафик приходит через согласованный TLS/reverse-proxy маршрут. Один сервер — возможная стартовая конфигурация, но её отказоустойчивость не подтверждена.

## Предлагаемая структура репозитория

```text
apps/web/                 # Next.js/Mantine
services/api/             # Go API
services/content-sync/    # если sync — отдельный сервис
packages/contracts/       # согласованные API/контент-схемы
infra/compose/            # Compose и образцы окружений
migrations/               # SQL-миграции
docs/                    # данный комплект
```

Пути условные. Выбор JS package manager и Go workspace открыт. Общие контракты не должны превращаться в зависимость Go-сервиса от Node runtime.

## Предлагаемая эксплуатация

Разделить local/staging/production; хранить только шаблоны переменных без секретов. Закреплять версии образов, проверять health/readiness, настраивать корректную остановку, ротацию логов и лимиты ресурсов. Для PostgreSQL хранить бэкапы вне единственного узла и регулярно проверять восстановление.

CI: сборка, статические проверки, существенные тесты API/ACL и миграций; затем отдельные поставки frontend и backend. Миграции запускать контролируемо один раз. При откате приложения учитывать совместимость схемы данных, а не автоматически откатывать БД.

Открыто: Hetzner-регион и тариф, ресурсы, reverse proxy, CI-провайдер, секрет-хранилище, RPO/RTO, мониторинг, резервирование, правила firewall и владелец эксплуатации.
