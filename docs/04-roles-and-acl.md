# Роли и ACL

[Оглавление](README.md) · [Вход](05-identity-and-slugs.md) · [Backend](10-backend-and-data.md)

**Задано:** роли и ACL. Названия и состав ролей ниже — предложение, а не восстановленная утверждённая матрица.

## Предлагаемая матрица

| Действие | Гость | Участник | Редактор | Модератор | Администратор |
|---|---|---|---|---|---|
| Читать публичное | Да | Да | Да | Да | Да |
| Менять свой профиль | Нет | Свой | Свой | Свой | Свой |
| Создавать Idea | Нет | Да | Да | Да | Да |
| Публиковать редакционный материал | Нет | Нет | В своей области | Нет по умолчанию | По явному праву |
| Модерировать контент | Нет | Нет | Нет по умолчанию | В своей области | По явному праву |
| Читать диалог | Нет | Если участник | Если участник | Если участник | Если участник |
| Назначать роли | Нет | Нет | Нет | Нет | По явному праву |

Роли можно совмещать; административная роль не должна автоматически открывать личную переписку. Особый доступ для расследований, если нужен, требует отдельной политики и аудита.

## Предлагаемая модель проверки

Субъект + разрешение + ресурс + контекст. Ресурсная область: свой объект, конкретная категория, весь проект. Использовать запрет по умолчанию. Проверять права в Go API для каждого действия; скрытая кнопка интерфейса не является защитой.

Учитывать владельца, статус объекта, членство в диалоге, блокировку аккаунта и область модератора. Отзыв прав должен влиять на активные сессии и кэши. Изменения ролей и критические действия записывать в аудит без секретов.

Открыто: окончательные роли, наследование, редакционные области, полномочия поддержки, апелляции, доступ к персональным данным и ответственный за изменение ACL.
