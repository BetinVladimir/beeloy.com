## Заданные области

Сообщество Beeloy.com, публичные slug, авторизация, мессенджер, Beeloy Ideas, мультиязычность и новостной контекст. Наличие конкретных типов публикаций, реакций и механик подписки в исходной беседе не удалось подтвердить.

## Предлагаемая карта продукта

| Область | Пользовательский результат | Статус детализации |
|---|---|---|
| Публичная часть | Чтение и переход по постоянной ссылке | Предложение |
| Профиль | Публичная идентичность и управление собственными данными | Предложение |
| Контент | Просмотр; создание и редактирование при наличии прав | Типы контента открыты |
| Ideas | Подача и отслеживание предложений | См. отдельный документ |
| Общение | Личные диалоги | Группы и вложения открыты |
| Управление | Модерация, роли, редакционная работа | Предлагаемая модель ACL |

## Предлагаемые UX-потоки

1. Гость открывает публичную страницу, выбирает язык, читает без обязательной регистрации.
2. Для защищённого действия система предлагает вход и сохраняет намерение пользователя.
3. После OTP или социального входа пользователь возвращается к действию.
4. В профиле доступны настройки языка, приватности и способов входа.
5. Автор Ideas видит статус и ответ команды; причины модерации объясняются.

Для основных экранов проектировать состояния загрузки, пустого результата, ошибки, отсутствия прав, удалённого контента и недоступной локализации. Формы должны поддерживать клавиатуру, видимый фокус, читаемые ошибки и мобильные экраны.

## Открытые границы

Нужны решения по ленте, категориям, поиску, комментариям, реакциям, подпискам, уведомлениям, редакционной CMS, монетизации и доступности. Ничего из этого не следует считать утверждённым MVP только на основании этого документа.
