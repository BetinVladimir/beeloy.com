# ТЗ Beeloy: разработка платформы (для автоматического исполнения)

Основа: материалы `docs/00..13` и уточнения заказчика от 04.11.2026. Материалы оставляют много вопросов «Открыто». Данное ТЗ **закрывает их решениями ТЗ-Dxx** (раздел 3). Решения заказчика помечены **[З]**, остальные — решения ТЗ; исполнитель их не пересматривает.

## 1. Как работать исполнителю (обязательные правила)

1. Читай файлы в порядке 01 → 10. Выполняй задачи из `09-tasks.md` строго по порядку T01, T02, …; не начинай задачу, пока не выполнены её зависимости.
2. Делай **только** то, что описано. Не добавляй функций, эндпоинтов, колонок, библиотек, не указанных в ТЗ. Если чего-то не хватает — остановись и запиши вопрос в `docs/tz/QUESTIONS.md`, затем продолжай с самым простым вариантом, совместимым с ТЗ.
3. Имена (пакеты, функции, таблицы, колонки, пути, коды ошибок, ключи конфигурации) используй **буквально** как в ТЗ.
4. Никаких ORM. SQL — только явный, параметризованный (`$1, $2`), никогда не склеивать строки из пользовательских данных.
5. Каждая задача считается выполненной, только если: код компилируется (`go build ./...` / `pnpm --dir apps/web build`), линтеры без ошибок (`go vet ./...`, `pnpm --dir apps/web lint`), тесты задачи написаны и проходят.
6. Права проверяются **только на сервере (Go)**. Фронтенд лишь скрывает кнопки.
7. Секреты, OTP-коды, токены сессий, тексты личных сообщений **никогда** не пишутся в логи.
8. Версии зависимостей: при установке брать актуальный стабильный релиз и **фиксировать точную версию** в `go.mod`/`pnpm-lock.yaml`. Мажорные версии не менять после установки.
9. Комментарии в коде — английские, короткие, только для неочевидного. Тексты интерфейса — только через ключи i18n (никаких строк в JSX, кроме dev-страниц).
10. Один коммит на задачу, сообщение `T<номер>: <название>`.
11. Тесты, требующие Ollama, используют заглушку HTTP-сервера (`httptest`); настоящий Ollama в автотестах не вызывается.

## 3. Принятые решения

| ID | Решение |
|---|---|
| ТЗ-D01 **[З]** | **Один сайт — beeloy.com** (`apps/web`). Домен beeloy.org и его витрина **не разрабатываются** (решение заказчика 04.11.2026); упоминания .org в исходных материалах `docs/00–13` считать неактуальными. Аккаунты и cookie — только на .com. |
| ТЗ-D02 **[З]** | **Схема входа трафика:** браузер → `beeloy.com` (Cloudflare, Next.js Worker) → `api-site.beeloy.com` (Cloudflare, DNS proxied) → **Caddy на Hetzner** (сертификат Cloudflare Origin CA + Authenticated Origin Pulls) → Go API. Для браузера единственный origin — `beeloy.com`: Worker проксирует `/api/*` на `https://api-site.beeloy.com` (REST и SSE, потоково), поэтому CORS не нужен, cookie сессии host-only на `beeloy.com`. SSR-запросы Worker идёт на тот же `api-site.beeloy.com`. Проверяется спайком T05 (потоковая передача SSE, `Set-Cookie`, настоящий IP клиента); запасной вариант — прямые запросы браузера на `api-site.beeloy.com` (потребует CORS и cookie `Domain=beeloy.com`, изменение ТЗ). |
| ТЗ-D03 | Next.js (App Router) на Cloudflare Workers через `@opennextjs/cloudflare`. Mantine v7+. Пакетный менеджер `pnpm`. |
| ТЗ-D04 | Go (актуальная стабильная), `github.com/go-chi/chi/v5`, `github.com/jackc/pgx/v5` (+`pgxpool`), `github.com/golang-migrate/migrate/v4` (SQL-файлы), `github.com/redis/go-redis/v9`, `github.com/google/uuid` (UUIDv7), `log/slog`, `github.com/aws/aws-sdk-go-v2` (S3), `github.com/wneessen/go-mail`, `github.com/stretchr/testify`, `testcontainers-go` (Postgres, Redis, MinIO). Ollama вызывается обычным HTTP-клиентом `net/http`. sqlc и ORM **не используются**. |
| ТЗ-D05 | Идентификаторы: UUIDv7, генерируются в Go. Время: `timestamptz`, UTC. Email хранится в нижнем регистре, `strings.TrimSpace`. |
| ТЗ-D06 **[З]** | **Вход только по email-OTP.** Google/Facebook и любые соцсети **не реализуются** (ни кода, ни ENV, ни кнопок). OTP: 6 цифр, TTL 10 мин, 5 попыток, повтор не чаще 1/60 с, лимит 5/час на email и 20/час на IP. Хранение в Redis (HMAC-SHA256). Redis недоступен → `503 unavailable`. Регистрация и вход — один поток: неизвестный email создаёт аккаунт. |
| ТЗ-D07 | Сессия: непрозрачный токен 32 байта, в БД SHA-256, cookie `bl_session` (HttpOnly, Secure, SameSite=Lax, Path=/), 30 дней со скользящим продлением раз в сутки. CSRF: заголовки `Origin` (из списка) и `X-Requested-With: beeloy` на небезопасных методах. Роли читаются из БД на каждый запрос. |
| ТЗ-D08 | Slug: ASCII `^[a-z0-9]+(-[a-z0-9]+)*$`, 3–32 (user) / 3–80 (idea, article), регистр не учитывается, публичный адрес профиля `/{locale}/people/{slug}`, зарезервированный список; старые slug закреплены за владельцем и дают 308-редирект; смена slug пользователя — раз в 30 дней. Slug статьи един для всех языков. |
| ТЗ-D09 | Роли: `member` (неявная), `editor`, `moderator`, `admin`. Область (`scope`) — только для `editor` (глобально или по категории). Админ не читает чужие диалоги. |
| ТЗ-D10 **[З]** | **Статьи и переводы живут в S3 JSON** (источник истины текстов). **В PostgreSQL — только состояния и индексы поиска**: категория, статус, видимость, ревизии, список файлов версий (заголовок и аннотация для карточек, tsvector), живой индекс опубликованного. Тело статьи в БД не хранится; БД-часть восстанавливается из S3 синхронизацией, кроме решений модерации (статус, видимость, `published_rev`, `article_access`) — они существуют только в БД и входят в бэкап. |
| ТЗ-D11 **[З]** | **26 языков; локализация локальными моделями Ollama; публикация и перевод пока вручную; ресурсы со статьями публикуются уже с переводом.** Автоматического перевода при публикации **нет**. Переводы появляются в S3 тремя способами: (а) готовые файлы переводов, выложенные вместе со статьёй; (б) ручная загрузка редактором через API; (в) оператор запускает CLI `translator` (Ollama, см. 10) по запросу, не демоном. Публикация статьи — всегда ручное действие редактора. Словари интерфейса: исходник `en` в репозитории, 25 остальных генерирует CLI `translator ui` через Ollama, оператор публикует их в S3 релизом. **26 языков = 24 официальных языка ЕС + русский + украинский:** bg, hr, cs, da, nl, en, et, fi, fr, de, el, hu, ga, it, lv, lt, mt, pl, pt, ro, sk, sl, es, sv, ru, uk (единственный источник — `contracts/locales.json`). Приоритет рынка — болгарский: язык по умолчанию (корневой редирект, `x-default`) `bg`; язык-запасной для контента `en`; язык-источник словарей интерфейса `en`. Арабского/иврита в списке нет, но поддержка `dir: rtl` в коде остаётся. Исходный язык статьи (`source_locale`) задаётся при её создании. Все URL с префиксом `/{locale}/`. |
| ТЗ-D12 **[З]** | **Content Sync Worker — да** (отдельный Go-процесс `cmd/content-sync`, не Cloudflare Worker). Два прогона: словари интерфейса (раз в 5 мин) и индексация статей (раз в 1 мин). Правка через API пишет в S3 и сразу обновляет состояние в БД (write-through); синхронизация подхватывает файлы, выложенные снаружи (готовые переводы, CLI). |
| ТЗ-D13 | Поиск: PostgreSQL FTS (`simple`-конфигурация) + триграммы (`pg_trgm`) для CJK и опечаток по полям заголовок+аннотация+тело (тело — только в tsvector, не как текст). Эндпоинт `GET /search/articles`. |
| ТЗ-D14 | Ideas: публичное чтение; подача только вошедшими; один голос на пользователя за идею; обсуждение — через общую систему комментариев (D21); подача ≤ 5 в сутки. Статусы и переходы — в 04. |
| ТЗ-D15 | Мессенджер: личные диалоги 1:1; **писать может любой зарегистрированный пользователь любому другому** (без подписки и разрешения). **Первое сообщение незнакомому идёт как «запрос на переписку»** (получатель принимает или отклоняет; до ответа отправитель может отправить не более 3 сообщений). Защита: лимит новых диалогов, блокировки, жалобы, защита от массовой рассылки, ограничение ссылок для новых аккаунтов, отключение уведомлений по диалогу (`muted`). Текст ≤ 4000, без вложений, редактирования и E2E. HTTP + SSE, fan-out через Redis Pub/Sub, история в PostgreSQL. |
| ТЗ-D16 | Cookie: только необходимые (`bl_session`, `bl_locale`, `bl_consent`; `bl_theme` — по выбору пользователя). Аналитики и рекламы в MVP нет. |
| ТЗ-D17 | Удаление аккаунта: `pending_deletion` 30 дней (можно отменить) → задание очистки анонимизирует данные. Экспорт — синхронный JSON `GET /me/export`. |
| ТЗ-D18 | Инфраструктура: один сервер Hetzner, Docker Compose, Caddy с Cloudflare Origin CA + Authenticated Origin Pulls, бэкапы `restic`, ежемесячная проверка восстановления. **Ollama в Compose не входит**: сервис `translator` обращается по `OLLAMA_URL` к внешнему хосту (GPU-машина или тот же сервер — решает владелец). |
| ТЗ-D19 **[З]** | Юридические тексты (Privacy, Cookies, Terms, Rules) — заглушки `TODO-LEGAL`, содержание согласуется юристом отдельно. |
| ТЗ-D21 **[З]** | **Комментарии** к статьям и идеям (в них всегда видны `nickname` и кликабельный `@slug` автора; упоминания `@slug` в тексте кликабельны). Один уровень ответов, ≤ 2000 символов. Обсуждения, компании и отзывы — этап P1, вне MVP. |
| ТЗ-D22 **[З]** | **Slug у каждого пользователя публичный**: профиль `/{locale}/people/{slug}`; поиск людей по `slug` и `nickname` (в том числе частичный); `email` непубличен. Поле отображаемого имени называется `nickname`. |
| ТЗ-D23 **[З]** | **Публикация утверждает модератор и определяет доступ** (`public` / `restricted` для назначенных пользователей). Загрузка файлов в S3 ничего не публикует. Новая ревизия уже опубликованной статьи невидима до повторного утверждения. Роль `editor` пишет и отправляет на проверку, но не публикует. |
| ТЗ-D24 | Принятие Terms/Privacy фиксируется при создании аккаунта в `user_agreements` (версии из конфигурации). Поиск построен за интерфейсом `SearchProvider` (замена движка без смены API). |
| ТЗ-D25 **[З]** | **Transactional outbox + Redis Streams.** Каждое значимое изменение пишет событие в таблицу `outbox_events` в той же транзакции; relay доставляет его в Redis Stream `events:main`; потребители (consumer groups) обрабатывают at-least-once, идемпотентно. В MVP потребитель один — `realtime` (доставка событий мессенджера в SSE), структура допускает новые без изменения доменного кода. Тексты сообщений и персональные данные в событиях **не передаются** (только идентификаторы). |
| ТЗ-D26 **[З]** | **Единый реестр ресурсов** `resources` (UUID, тип, владелец, статус, видимость) для `user`, `article`, `idea`, `comment`: общие механизмы проверки видимости жалоб, постоянные ссылки `/{locale}/r/{uuid}` → канонический адрес, сверка. Специфические поля остаются в таблицах сущностей; личные сообщения в реестре **не** участвуют. |
| ТЗ-D20 | Каждый файл перевода содержит `origin`: `human` (выложен с ресурсом или загружен редактором) или `machine` (создан CLI через Ollama). Для `machine` на странице показывается `article.machine_translated_notice`. Локаль видна читателям, если файл входит в живой индекс утверждённой модератором ревизии (04 §1.2). |

## 4. Глоссарий

- **Subject** — аутентифицированный пользователь (`UserID`, `Status`, список `Binding`).
- **Resource** — объект, к которому применяется право (тип, владелец, категория).
- **Binding** — запись роли пользователя с областью действия.
- **Slug** — публичный человекочитаемый идентификатор; внутренний ключ всегда UUID.
- **Release (i18n)** — полная версия набора словарей интерфейса всех языков.
- **Rev** — монотонный номер ревизии исходного текста статьи; файлы ревизий неизменяемы.
- **Source locale** — язык, на котором написан оригинал статьи.

## 5. Вне объёма MVP (не делать)

Вход через соцсети, MFA, обсуждения (форум), каталог компаний и отзывы,  группы и вложения в мессенджере, push-уведомления, комментарии, подписки, монетизация, аналитика, E2E-шифрование, реакции, локализованные slug, WYSIWYG-редактор (используется Markdown-textarea), автоматический перевод при публикации и фоновая очередь переводов, очистка старых ревизий в S3.

## 6. Известные риски (для информации заказчика)

- Качество и скорость машинного перевода на CPU: 25 переводов длинной статьи могут занимать часы; поэтому CLI запускается оператором вручную, по одной статье.
- Нерецензируемый машинный перевод может влиять на SEO и репутацию; поэтому помечается в интерфейсе и в данных (ТЗ-D20).
- Поиск по `simple`-конфигурации не делает морфологию; для 26 языков это осознанный компромисс.
