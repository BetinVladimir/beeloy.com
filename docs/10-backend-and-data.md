# Go backend, PostgreSQL без ORM и Redis

[Оглавление](README.md) · [ACL](04-roles-and-acl.md) · [Инфраструктура](12-infrastructure-and-monorepo.md)

## Задано

Go backend; PostgreSQL без ORM; Redis. Это базовый стек из текущего запроса, а не проверенное состояние репозитория.

## Предлагаемые границы

Go API отвечает за авторизацию, ACL, продуктовые операции, SQL-транзакции и интеграции. Next.js не дублирует правила доступа. Конкретный API-стиль, Go router, SQL driver и инструменты генерации запросов открыты.

PostgreSQL — источник истины для аккаунтов, связей провайдеров, контента, Ideas, ролей и истории сообщений. Отсутствие ORM означает явные SQL-запросы, параметризацию, миграции и контролируемые транзакции. SQL-генератор при необходимости согласовать отдельно: его допустимость не следует из выбора «без ORM».

Redis — кандидат для TTL-кэша, ограничений частоты, краткоживущих состояний и событий присутствия. Для каждой функции определить поведение при недоступности Redis. Критичные проверки безопасности не должны молча отключаться. Сессии и OTP могут использовать Redis только с явно заданными сроками и последствиями потери данных.

## Предлагаемые группы сущностей

- Identity: users, auth_identities, sessions, slug_history.
- Access: roles, permissions, role_bindings и resource scope.
- Content: модель публикаций и их переводов после согласования продукта.
- Ideas: ideas, status_history, при необходимости votes/comments.
- Messenger: conversations, members, messages, read_cursors.
- Operations: audit_events, sync_runs и указатель версии переводов при выбранной модели хранения.

Это карта доменов, не готовая ER-схема. Все имена условные.

## Предлагаемые инженерные требования

Уникальные ограничения для provider identity и slug; внешние ключи; индексы по фактическим запросам; пагинация; контекстные таймауты; ограничение размера запросов; управляемый пул соединений. Для повторяемых операций применять ключи идемпотентности.

Проверки: попытка доступа к чужому объекту, откат транзакции, параллельное присвоение slug, повтор отправки сообщения, отзыв роли, ошибки Redis и БД. Миграции должны быть совместимы с последовательным обновлением версий. Бэкап считается пригодным после проверенного восстановления.
