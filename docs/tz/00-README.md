# ТЗ Beeloy: разработка платформы (для автоматического исполнения)

Основа: материалы `docs/00..13` и доступные пользовательские сообщения от 04.11.2026. Исторически полный текст исходной беседы недоступен: read_thread вернул ссылки-заглушки вместо ответов. Источник требований — явный запрос пользователя в текущей переписке. **[З]** означает требование, прямо присутствующее в доступных пользовательских сообщениях; **[Т]** — техническая детализация ТЗ, без утверждения о её историческом согласовании. Если прежнее ТЗ приписывало заказчику неподтверждённое уточнение, такая атрибуция снимается. Точная философия, перечень языков и остальные неподтверждённые продуктовые детали остаются рабочей детализацией, а не цитатой из переписки.

## 1. Как работать исполнителю (обязательные правила)

1. Читай файлы в порядке 00 → 10. Выполняй задачи из `09-tasks.md` строго по порядку T01, T02, …; не начинай задачу, пока не выполнены её зависимости.
2. Делай **только** то, что описано. Не добавляй функций, эндпоинтов, колонок, библиотек, не указанных в ТЗ. Если существенного требования не хватает — запиши вопрос в `docs/tz/QUESTIONS.md`; зависимую работу не додумывай, продолжай независимые задачи. При конфликте приоритет имеют явные требования пользователя, затем профильный контракт ТЗ; противоречие между контрактами необходимо устранить до реализации.
3. Имена (пакеты, функции, таблицы, колонки, пути, коды ошибок, ключи конфигурации) используй **буквально** как в ТЗ.
4. Никаких ORM. SQL — только явный, параметризованный (`$1, $2`), никогда не склеивать строки из пользовательских данных.
5. Каждая задача считается выполненной, только если: код компилируется (`go build ./...` / `pnpm --dir apps/web build` и `pnpm --dir apps/org build`), линтеры без ошибок (`go vet ./...`, `pnpm --dir apps/web lint` и `pnpm --dir apps/org lint`), тесты задачи написаны и проходят.
6. Права проверяются **только на сервере (Go)**. Фронтенд лишь скрывает кнопки.
7. Секреты, OTP-коды, токены сессий, тексты личных сообщений **никогда** не пишутся в логи.
8. Версии зависимостей: при установке брать актуальный стабильный релиз и **фиксировать точную версию** в `go.mod`/`pnpm-lock.yaml`. Мажорные версии не менять после установки.
9. Комментарии в коде — английские, короткие, только для неочевидного. Тексты интерфейса — только через ключи i18n (никаких строк в JSX, кроме dev-страниц).
10. Один коммит на задачу, сообщение `T<номер>: <название>`.
11. Тесты, требующие Ollama, используют заглушку HTTP-сервера (`httptest`); настоящий Ollama в автотестах не вызывается.

## 3. Требования и техническая детализация

| ID | Решение |
|---|---|
| ТЗ-D01 **[З]** | **Бренд-архитектура: beeloy.org — витрина проекта (`apps/org`), beeloy.com — сообщество (`apps/web`).** На .org — миссия, о проекте, краткие правила, контакты и переход в .com. Авторизация и сообщество — на .com; общая cookie между .org и .com не используется. |
| ТЗ-D02 **[Т]** | **Схема входа трафика:** браузер → `beeloy.com` (Cloudflare, Next.js Worker) → `api-site.beeloy.com` (Cloudflare, DNS proxied) → **Caddy на Hetzner** (сертификат Cloudflare Origin CA + Authenticated Origin Pulls) → Go API. Для браузера единственный origin — `beeloy.com`: Worker проксирует `/api/*` на `https://api-site.beeloy.com` (REST и SSE, потоково), поэтому CORS не нужен, cookie сессии host-only на `beeloy.com`. SSR-запросы Worker идёт на тот же `api-site.beeloy.com`. Проверяется спайком T05 (потоковая передача SSE, `Set-Cookie`, настоящий IP клиента); запасной вариант — прямые запросы браузера на `api-site.beeloy.com` (потребует CORS и cookie `Domain=beeloy.com`, изменение ТЗ). |
| ТЗ-D03 **[Т]** | Next.js (App Router) на Cloudflare Workers через `@opennextjs/cloudflare`. Mantine v7+. Пакетный менеджер `pnpm`. |
| ТЗ-D04 **[Т]** | Go (актуальная стабильная), `github.com/go-chi/chi/v5`, `github.com/jackc/pgx/v5` (+`pgxpool`), `github.com/golang-migrate/migrate/v4` (SQL-файлы), `github.com/redis/go-redis/v9`, `github.com/google/uuid` (UUIDv7), `log/slog`, `github.com/aws/aws-sdk-go-v2` (S3), `github.com/wneessen/go-mail`, `github.com/stretchr/testify`, `testcontainers-go` (Postgres, Redis, MinIO). Ollama вызывается обычным HTTP-клиентом `net/http`. sqlc и ORM **не используются**. |
| ТЗ-D05 **[Т]** | Идентификаторы: UUIDv7, генерируются в Go. Время: `timestamptz`, UTC. Email хранится в нижнем регистре, `strings.TrimSpace`. |
| ТЗ-D06 **[З]** | **Способы входа: OTP, Google и Facebook.** Для OTP используется email (техническая детализация). Социальные способы не исключаются из MVP. Лимиты OTP: 6 цифр, TTL 10 мин, 5 попыток, повтор не чаще 1/60 с, 5/час на email и 20/час на IP. Одноразовость обеспечивается атомарно в Redis; Redis недоступен → `503 unavailable`. Подробный контракт identity — 03 §5–8. |
| ТЗ-D07 **[Т]** | Сессия: непрозрачный токен 32 байта, в БД SHA-256, cookie `bl_session` (HttpOnly, Secure, SameSite=Lax, Path=/), 30 дней со скользящим продлением раз в сутки. CSRF: заголовки `Origin` (из списка) и `X-Requested-With: beeloy` на небезопасных методах. Роли читаются из БД на каждый запрос. |
| ТЗ-D08 **[Т]** | Slug: ASCII `^[a-z0-9]+(-[a-z0-9]+)*$`, 3–32 (user) / 3–80 (idea, article), регистр не учитывается, публичный адрес профиля `/{locale}/people/{slug}`, зарезервированный список; старые slug закреплены за владельцем и дают 308-редирект; смена slug пользователя — раз в 30 дней. Slug статьи един для всех языков. |
| ТЗ-D09 **[Т]** | Роли: `member` (неявная), `editor`, `moderator`, `admin`. Область (`scope`) — только для `editor` (глобально или по категории). Админ не читает чужие диалоги. |
| ТЗ-D10 **[З]** | **Готовые переводы — S3 JSON; PostgreSQL без ORM.** Разделение состояния статей/индексов и S3-текстов в 02/04 — техническая детализация [Т]. БД не хранит body_md, решения модерации находятся в БД; восстановление требует согласованного бэкапа БД и объектов S3. |
| ТЗ-D11 **[Т]** | **26 языков [З]; конкретный список и локализация локальными моделями Ollama [Т]; публикация и перевод пока вручную; ресурсы со статьями публикуются уже с переводом.** Автоматического перевода при публикации **нет**. Переводы появляются в S3 тремя способами: (а) готовые файлы переводов, выложенные вместе со статьёй; (б) ручная загрузка редактором через API; (в) оператор запускает CLI `translator` (Ollama, см. 10) по запросу, не демоном. Публикация статьи — ручное действие модератора; редактор готовит и отправляет материал на проверку. Словари интерфейса: исходник `en` в репозитории, 25 остальных генерирует CLI `translator ui` через Ollama, оператор публикует их в S3 релизом. **26 языков = 24 официальных языка ЕС + русский + украинский:** bg, hr, cs, da, nl, en, et, fi, fr, de, el, hu, ga, it, lv, lt, mt, pl, pt, ro, sk, sl, es, sv, ru, uk (единственный источник — `contracts/locales.json`). Приоритет рынка — болгарский: язык по умолчанию (корневой редирект, `x-default`) `bg`; язык-запасной для контента `en`; язык-источник словарей интерфейса `en`. Арабского/иврита в списке нет, но поддержка `dir: rtl` в коде остаётся. Исходный язык статьи (`source_locale`) задаётся при её создании. Все URL с префиксом `/{locale}/`. |

| ТЗ-D13 **[Т]** | Поиск: PostgreSQL FTS (`simple`) по заголовку, аннотации и телу; триграммы (`pg_trgm`) — только по заголовку и аннотации. Подстрочный поиск по телу для CJK не обещается. Эндпоинт `GET /search/articles`. |
| ТЗ-D14 **[Т]** | Ideas: публичное чтение; подача только вошедшими; один голос на пользователя за идею; обсуждение — через общую систему комментариев (D21); подача ≤ 5 в сутки. Статусы и переходы — в 04. |
| ТЗ-D15 **[Т]** | Мессенджер: личные диалоги 1:1; **писать может любой зарегистрированный пользователь любому другому** (без подписки и разрешения). **Первое сообщение незнакомому идёт как «запрос на переписку»** (получатель принимает или отклоняет; до ответа отправитель может отправить не более 3 сообщений). Защита: лимит новых диалогов, блокировки, жалобы, защита от массовой рассылки, ограничение ссылок для новых аккаунтов, отключение уведомлений по диалогу (`muted`). Текст ≤ 4000, без вложений, редактирования и E2E. HTTP + SSE, fan-out через Redis Pub/Sub, история в PostgreSQL. |
| ТЗ-D16 **[Т]** | Cookie: необходимые bl_session, bl_locale, bl_consent и краткоживущие bl_oauth_flow/bl_onboarding для Google/Facebook; bl_theme — по выбору пользователя. Аналитики и рекламы в MVP нет. |

Миссия — `docs/ Mission.md` (английский эталон — ключи `org.mission.*`). |
| ТЗ-D21 **[Т]** | **Комментарии** к статьям и идеям (в них всегда видны `nickname` и кликабельный `@slug` автора; упоминания `@slug` в тексте кликабельны). Один уровень ответов, ≤ 2000 символов. Обсуждения, компании и отзывы — этап P1, вне MVP. |
| ТЗ-D22 **[Т]** | **Slug у каждого пользователя публичный**: профиль `/{locale}/people/{slug}`; поиск людей по `slug` и `nickname` (в том числе частичный); `email` непубличен. Поле отображаемого имени называется `nickname`. |
| ТЗ-D23 **[Т]** | **Публикация утверждает модератор и определяет доступ** (`public` / `restricted` для назначенных пользователей). Загрузка файлов в S3 ничего не публикует. Новая ревизия уже опубликованной статьи невидима до повторного утверждения. Роль `editor` пишет и отправляет на проверку, но не публикует. |
| ТЗ-D24 **[Т]** | Принятие Terms/Privacy фиксируется при создании аккаунта в `user_agreements` (версии из конфигурации). Поиск построен за интерфейсом `SearchProvider` (замена движка без смены API). |
| ТЗ-D25 **[Т]** | **Transactional outbox + Redis Streams.** Каждое значимое изменение пишет событие в таблицу `outbox_events` в той же транзакции; relay доставляет его в Redis Stream `events:main`; потребители (consumer groups) обрабатывают at-least-once, идемпотентно. В MVP потребитель один — `realtime` (доставка событий мессенджера в SSE), структура допускает новые без изменения доменного кода. Тексты сообщений и тексты, контакты и токены в событиях **не передаются** (технические идентификаторы/состояния сохраняются как псевдонимные данные по политике хранения). |
| ТЗ-D26 **[Т]** | **Единый реестр ресурсов** `resources` (UUID, тип, владелец, статус, видимость) для `user`, `article`, `idea`, `comment`: общие механизмы проверки видимости жалоб, постоянные ссылки `/{locale}/r/{uuid}` → канонический адрес, сверка. Специфические поля остаются в таблицах сущностей; личные сообщения в реестре **не** участвуют. |
| ТЗ-D20 **[Т]** | Каждый файл перевода содержит `origin`: `human` (выложен с ресурсом или загружен редактором) или `machine` (создан CLI через Ollama). Для `machine` на странице показывается `article.machine_translated_notice`. Локаль видна читателям, если файл входит в живой индекс утверждённой модератором ревизии (04 §1.2). |

## 4. Глоссарий

- **Subject** — аутентифицированный пользователь (`UserID`, `Status`, список `Binding`).
- **Resource** — объект, к которому применяется право (тип, владелец, категория).
- **Binding** — запись роли пользователя с областью действия.
- **Slug** — публичный человекочитаемый идентификатор; внутренний ключ всегда UUID.
- **Release (i18n)** — полная версия набора словарей интерфейса всех языков.
- **Rev** — монотонный номер ревизии исходного текста статьи; файлы ревизий неизменяемы.
- **Source locale** — язык, на котором написан оригинал статьи.

## 5. Вне объёма MVP (не делать)

MFA, обсуждения (форум), каталог компаний и отзывы,  группы и вложения в мессенджере, push-уведомления, подписки, монетизация, аналитика, E2E-шифрование, реакции, локализованные slug, WYSIWYG-редактор (используется Markdown-textarea), автоматический перевод при публикации и фоновая очередь переводов, очистка старых ревизий в S3.

## 6. Известные риски (для информации заказчика)

- Качество и скорость машинного перевода на CPU: 25 переводов длинной статьи могут занимать часы; поэтому CLI запускается оператором вручную, по одной статье.
- Нерецензируемый машинный перевод может влиять на SEO и репутацию; поэтому помечается в интерфейсе и в данных (ТЗ-D20).
- Поиск по `simple`-конфигурации не делает морфологию; для 26 языков это осознанный компромисс.

## 7. Источники, соответствие переписке и приёмка редакции

Прямо заданы пользователем: философия проекта (её точная формулировка не предоставлена); .org-витрина/.com-сообщество; Ideas; роли/ACL; OTP/Google/Facebook; публичные slug; мессенджер; GDPR/cookies; SEO; 26 языков; готовые переводы S3 JSON; Content Sync Worker; Redis; PostgreSQL без ORM; Go; Next.js/Mantine на Cloudflare; Hetzner/Docker Compose; монорепо. Эти требования нельзя отменять ссылкой на неподтверждённые «уточнения заказчика» в прежней редакции.

Список 24 языка ЕС + ru/uk, default=bg, Ollama, конкретные роли, запросы на переписку, outbox/Streams и реестр ресурсов — рабочая техническая/продуктовая детализация [Т], унаследованная из локального ТЗ. Она не удостоверяется доступной историей. Вернуть исходные формулировки философии и окончательно сверить эти параметры можно после получения полного текста беседы. Никакой суммы бюджета или срока из недоступной истории это ТЗ не устанавливает.

Обязательная политика исправлений: (1) изменяемый контент не кэшируется общими HTTP/Next.js кэшами; (2) ревизии и переводы неизменяемы, `translator --force` не перезаписывает их; (3) публичные чтения комментариев учитывают видимость цели; (4) OTP и ограничения отправки проверяются конкурентно безопасно; (5) последний активный администратор защищён во всех потоках; (6) бэкап включает S3; (7) новые тесты выполняются заново. `DONE.md` и `SPIKE-T05.md` описывают прежние проверки и не доказывают соответствие этой редакции.
