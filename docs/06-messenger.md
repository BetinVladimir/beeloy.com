# Мессенджер

[Оглавление](README.md) · [ACL](04-roles-and-acl.md) · [Хранение](10-backend-and-data.md)

**Задано:** мессенджер в сообществе. Формат диалогов, транспорт, вложения и гарантии шифрования остаются открытыми.

## Предлагаемый минимальный объём

Личные диалоги, история сообщений, непрочитанное, блокировка отправителя и жалоба. Группы, звонки, исчезающие сообщения, редактирование, поиск и вложения не включать автоматически в первую версию.

Сущности-кандидаты: conversation, conversation_member, message, read_cursor. PostgreSQL — долговременное хранение. Redis может обслуживать присутствие и доставку событий, но не быть единственным хранилищем истории.

## Предлагаемые гарантии

Проверять членство при чтении истории, отправке, подписке на события и получении вложения. Клиентский идентификатор отправки помогает исключать дубли при повторе запроса. Порядок сообщений определяется сервером; после переподключения клиент восстанавливает пропущенное по курсору.

WebSocket или SSE плюс HTTP — открытый выбор после проверки маршрута Cloudflare → Hetzner. Push-уведомления и письма не должны раскрывать приватный текст без согласованной настройки.

TLS защищает передачу; сквозное шифрование не заявлено и требует самостоятельного решения по ключам, восстановлению и модерации. Правила хранения сообщений, удаления у участников и доступа при жалобах согласовать с [политикой приватности](07-privacy-and-cookies.md).

Риски: спам, преследование, перебор ID, утечки через уведомления, потеря событий Redis и неверная изоляция диалогов.
